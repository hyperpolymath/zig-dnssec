= Fuzz testing
:toc:

== Targets

All targets live in `tests/fuzz_targets.zig` and take arbitrary bytes:

[cols="1,3",options="header"]
|===
| Target | What it checks
| `decodeRaw` | DNS message decoder on raw bytes; anything that parses must re-encode and re-parse to the same records
| `decodeMutated` | the same, on recorded responses from `tests/testdata/crosscheck.traces` under a small mutation language (bit flips, byte set/insert/delete, truncation, interesting 16-bit values, chunk duplication)
| `nsec3` | NSEC3 RDATA parsing, owner-label decoding, and every NSEC3 proof on arbitrary records and query names; type-bitmap parsing; Base32hex decoding
| `presentation` | the presentation-format (zone file) parser
| `validatorDifferential` | the whole validator: fails if a mutation of any recorded response produces a secure answer different from the unmutated one
|===

== Running

[source,console]
----
zig build test                                              # replays the corpus below once
zig build fuzz --fuzz=3M -Doptimize=ReleaseSafe              # coverage-guided, first four targets
zig build fuzz-validator --fuzz=30K -Doptimize=ReleaseSafe   # coverage-guided, differential target
zig build fuzz-tool -Doptimize=ReleaseSafe
./zig-out/bin/dnssec-fuzz all 60 0x2026                      # reproducible mutation fuzzer, 60 s per target
----

Crashing inputs from the coverage-guided fuzzer are saved under `.zig-cache/f/`. Keep
each one in `corpus/` and add it to the `corpus` list of the matching test in
`tests/fuzz.zig`, so that `zig build test` replays it.

== Corpus

`corpus/decode-mutated-0001.bin`:: integer overflow in name decoding at the 255-octet
boundary (found 2026-10-13, fixed).

Results of the campaigns run so far are in `docs/reports/VERIFICATION.adoc`.
