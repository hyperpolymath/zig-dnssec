= zig-dnssec Roadmap

== Current status

Experimental. Milestone 1 (codec, DNSSEC validation, DoH stub) and milestone 2 (the C
ABI seam) are complete and tested, and have *not* been independently reviewed. See
`docs/reports/VERIFICATION.adoc` for what is and is not verified.

== Milestone 1 — codec, validator, DoH stub (done, 2026-10-13)

* [x] RFC 1035 wire codec with strict decoding and name compression
* [x] DNSSEC signature verification (algorithms 5, 7, 8, 10, 13, 14, 15)
* [x] NSEC / NSEC3 denial of existence
* [x] Chain-of-trust validator with explicit, non-downgradable verdicts
* [x] DoH stub client and CLI
* [x] Fuzzing (coverage-guided and standalone) with corpus
* [x] Cross-check against Unbound and ldns on a fixed zone set
* [x] CI workflow running the tests

== Milestone 2 — C ABI seam (done, 2026-10-13)

* [x] C header as the contract (`src/interface/ffi/include/zig_dnssec.h`), version 1
* [x] Pure-Zig implementation, type-checked against the header at compile time
* [x] Idris2 model: codes with round-trip proofs, verdict layout proofs, and a result
      type that cannot carry an answer for a bogus or indeterminate verdict
* [x] Tests keeping header, Zig and Idris2 in step; C-ABI behaviour tests
* [x] Idris2 -> C ABI -> Zig end-to-end test, in CI

== Next

. *Independent review* of the validator, the proof logic, the parsers and the DoH
  transport — before anything else relies on this code.
. Report the Zig 0.17.0 `std.http.Client` CONNECT/TLS defect upstream.
. Upstream the `rsr-template-repo` issues met at mint (`RSR_NON_INTERACTIVE=1` loops
  on prompts, as the template's onboarding docs warn; a table cell lost to placeholder
  deletion; references to the template's own issues renamed by the global
  substitution; REPOSITORY-MAP.adoc and the coaptation receipt left stale; the
  template's example ABI/FFI seam, which does not build on Zig 0.17.0 and whose
  Idris2 and Zig sides disagree on result codes and symbol names); add a
  Zig-library archetype so `build.zig` and `build.zig.zon` are expected at the root.
. A live transport for Idris2 callers: a DNS-over-HTTPS entry point in the C ABI, or
  an Idris2 callback for `zig_dnssec_validate`.
. A model of the validator's decision procedure in which "secure" can only be built
  from verified signatures up to an anchor (`docs/reports/VERIFICATION.adoc`, estate
  note).

== Later

* DNS-over-QUIC transport (needs a QUIC implementation).
* HTTP/2 for DoH.
* Ed448 once it is available from a vetted pure-Zig implementation.
* RFC 5011 trust-anchor rollover; negative trust anchors.
* A cache, with aggressive NSEC use (RFC 8198).
* Run the live-resolver smoke tests on a schedule.
