= AI-Assisted Installation Guide
:toc:
:toclevels: 3

This guide is for an **AI agent** setting up zig-dnssec for development or for a
review. A human following it will not be misled.

[[ai-implementation]]
== Implementation for an AI agent

=== 1. Orient before acting

Read, in this order, before running anything:

. `zig-dnssec_chora.deed` — the repo deed (what this repository is and is not).
. `CLAUDE.md` — the generated arrival pack (estate doctrine and repo identity).
. `docs/status/ROADMAP.adoc` — milestones and next actions.
. `docs/architecture/THREAT-MODEL.adoc` and `docs/reports/VERIFICATION.adoc` — what the
  validator promises, its known gaps, and what has been verified.

The code is experimental and unreviewed. Do not describe it as production-ready.

=== 2. Obtain the source

[source,bash]
----
git clone https://github.com/hyperpolymath/zig-dnssec.git
cd zig-dnssec
----

=== 3. Install the toolchain

The toolchain is pinned in `mise.toml` / `mise.lock` (Zig 0.17.0, just, shellcheck).

[source,bash]
----
just setup        # installs the pinned tools per user with mise
just doctor       # reports anything missing
----

Without mise: download Zig 0.17.0 from https://ziglang.org/download/ and check its
SHA-256 against `mise.lock` (or its minisign signature) before use.

=== 4. Build and test

[source,bash]
----
zig build test --summary all            # unit, RFC-vector, denial, replay, fuzz-corpus tests
zig build -Doptimize=ReleaseSafe        # library + dnssec-stub
just validate                           # repository-standard checks
----

All tests run offline. The cross-check against Unbound and ldns
(`tests/crosscheck/`) needs NSD, Unbound, ldns tools and haproxy; the `crosscheck`
target of `build/container/Containerfile` provides them.

== Privacy

Setting up transmits nothing beyond downloading the repository and the pinned tools.
The test suite makes no network requests. `dnssec-stub` contacts the DNS-over-HTTPS
server named on its command line (by default Quad9) and, if `https_proxy` is set, the
proxy; the DNS names you query are visible to that server.

If you are an agent acting on someone else's behalf, do not invent values the
repository does not record; report the gap instead.
