= zig-dnssec — Quick Start for Developers
:toc:
:toclevels: 2

== Tech Stack

Zig 0.17.0, with Idris2 0.7.0 for the ABI model. Tooling: `just` and Bash.

== Set Up Development Environment

=== Option A: Guix (preferred)

[source,bash]
----
guix shell
----

=== Option B: Manual

[source,bash]
----
git clone https://github.com/hyperpolymath/zig-dnssec.git
cd zig-dnssec
just setup-dev
----

== Build

[source,bash]
----
just build
----

== Test

[source,bash]
----
just test
----

== Project Structure

[source]
----
zig-dnssec/
├── src/                  # Source code
├── src/interface/Abi/              # Idris2 ABI definitions (if applicable)
├── ffi/zig/              # Zig FFI bridge (if applicable)
├── tests/                # Test suite
├── docs/                 # Documentation
├── .machine_readable/    # Checkpoint files (STATE, META, ECOSYSTEM)
├── Justfile              # Task runner recipes
├── build/                # Build orchestration (just/, guix.scm, container/)
└── *_chora.deed          # repo deed: AI entry point (allocation + ply tree)
----

== Before Submitting a PR

[source,bash]
----
just lint           # Format and lint
just test           # All tests pass
just panic-scan     # No new security issues
----

== Contractile Invariants

Read `.machine_readable/contractiles/must/must.k9.ncl` before making changes.
Key invariants that must never be violated:

The `must` contractile's project-specific invariants are pending owner
authorship (it still carries invariants inherited from the template). Until
they are declared, the repo deed `zig-dnssec_chora.deed` is the authority. Its
headline rule:

* Fail-closed DNSSEC verdicts: answer data is reachable only from a secure
  verdict or an insecure one that carries an authenticated proof.
