= zig-dnssec: what has been verified, and what has not
:toc:

Status as of 2026-10-13, Zig 0.17.0. Every claim below is tagged with the estate's
five statuses and names the artefact that discharges it. Nothing is tagged PROVEN:
there is no machine-checked proof in this repository yet.

[cols="1,4",options="header"]
|===
| Status | Meaning here
| PROVEN | discharged by a machine-checked proof (none yet)
| TESTED | discharged by a test or run that is in the repository and reproducible
| ASSUMED | relied on without being checked here
| DESIGNED | built and reasoned about, but not exercised by a test
| OPEN | not done
|===

== Cross-check detail

263 queries (13 per leaf zone plus root, TLD, DNAME, Opt-Out and DS-at-non-cut
queries), run by `tests/crosscheck/run.sh`:

* *vs Unbound, default policy: 17 disagreements.* 12 are the Ed448 zone (we cannot
  verify Ed448: `bogus/unsupported_algorithm`; Unbound: secure) and 5 are negative
  answers from the zone with 200 NSEC3 iterations (`bogus/nsec3_iterations_exceeded`;
  Unbound: insecure). Both are deliberate default policies.
* *vs Unbound, RFC-permissive policy: 12 disagreements*, all Ed448 (ours: insecure).
* *vs ldns `drill -S`: 33 outcomes incompatible with ours.* 16 are the Ed448 and
  iteration cases. In the other 17 Unbound agrees with us and `drill -S` is coarser:
  nine NSEC/NSEC3 empty-non-terminal or wildcard-NODATA proofs it does not chase, three
  Opt-Out answers it reports as secure (RFC 5155 §9.2 says they are not), two DNAME
  answers it does not follow, one CNAME whose (tampered) target it does not validate,
  and two DNSKEY queries on the expired and not-yet-valid zones that it reports as
  successful.
* The first run found a real bug: a DNAME answer was rejected because the unsigned
  synthesised CNAME was examined before the DNAME. Fixed; DNAME is now processed first.

== Fuzzing detail

* *Coverage-guided* (`zig build fuzz --fuzz=3M -Doptimize=ReleaseSafe`): decoder on raw
  bytes, decoder on mutated recorded responses, NSEC3 parser and proofs, presentation
  parser: 12.0 million runs in total ("Unique runs: 8887", coverage 1289 of 11272
  instrumented PCs, in the fuzzer's own report). An earlier
  500K run *found an integer overflow* in name decoding (u8 length arithmetic at the
  255-octet boundary). Fixed; the crashing input is in `tests/fuzz/corpus/` and is
  replayed by `zig build test`.
* *Differential validator target*: fails if a mutation of any recorded response yields a

== Findings outside this code

* *Zig 0.17.0 `std.http.Client` + CONNECT proxy sends HTTPS requests in cleartext*
  (`docs/developer/ZIG-STD-SURVEY.adoc`). Worth an upstream report.
* *RFC 8080 §6*: the example signatures carry Labels=3 for a two-label owner, which a
  validator must reject (`tests/vectors.zig`).
* `drill -S` reported success for the DNSKEY RRset of a zone whose signatures had
  expired a month earlier. Not investigated further; noted for whoever reviews ldns.

== Estate note: where a proof would go

The guarantee "answer data is only reachable with secure evidence or a proven-insecure
reason" is currently enforced by the shape of a Zig tagged union and by tests. It is the
kind of invariant the estate's epistemic-types work is meant to state: a `secure` answer
as knowledge, `insecure` as justified non-knowledge, and the absence of any path from
`bogus` to an answer. A small Idris2 model of `Verdict` at the ABI seam, with that
property as a type, is a short and legitimate next step; it would move the row
"Failures are never reported as insecure" from TESTED/DESIGNED towards PROVEN.
